# ScreenerPro (SmartMoneyBOS)

Long-only daily **crypto investment advisor webapp**. Fully static — no build step, no deps.

## Files
- `index.html` — UI: two tabs (Chart / **Compare** — all strategies × a user-editable symbol list), strategy dropdown, Advisor panel, equity backtest, mobile-responsive (media query at END of `<style>` so it wins the cascade). Fetches Binance spot klines client-side (`api.binance.com`, fallback `data-api.binance.vision`).
- **Compare tab** (Sep 2026): timeframes **1h/2h/4h/1d/1w**; symbol list is editable (`#cmpSyms`, comma-separated, bare tickers get `USDT` appended, persisted in `localStorage` under `smb.cmpSyms`, `Reset list` restores the 7-coin universe); unreachable/delisted symbols are named in `#cmpStatus` rather than silently dropped. **Bar count is user-set** (`#cmpBars`, 300–60000, persisted under `smb.cmpBars`, live "≈ N days/mo/yrs" readout in `#cmpSpan` that turns red under 200 days): it tracks `CMP_BARS[tf]` until the user types a number, then stays pinned across TF changes (`cmpBarsTouched`). `cmpCache` is keyed `sym|tf` storing `{rows, asked}` so lowering the count slices what is already held instead of refetching, and a symbol with genuinely short history is not refetched forever; `cmpRowsTf` is keyed `tf|bars`. The 300 floor exists because `runCompare` skips anything under 250 bars — don't lower it or the box can select a guaranteed-empty table. `#cmpStrat` options are **generated from `CMP_STRATS`** — never hand-write them again, that is how `composite`/`meanrev` survived their July 2026 removal as dead options. **Window sweep** (`#cmpSweep`, on by default) slides a window of 35% of history across the equity path inside `pathStats` — no extra engine runs, no extra fetches, so toggling it is a pure re-render. **Every run measures TWO windows**: the user's bar count *and* a fixed `CMP_REF_BARS`=10,000 reference, both sliced from one fetch (`need = max(bars, 10000)`) so the reference costs no extra requests — which also means raising the Bars box anywhere below 10,000 never refetches. Rows carry `{e:recent, d:reference, sameWin}`. **`#cmpPick`** renders the go-to combo above the table: it requires the FULL investment test (`okRow`, shared with the table's ✓) on the **reference**, plus only a form check on the recent window (`n>=3 && net>0 && edge>0`) — a short window cannot carry a 30-trade floor when `liqbrk` takes ~7 trades/year on 4h, so demanding it there would fail every window on arithmetic rather than merit. Ranked by **reference** edge, never the noisy recent one. The panel is a hero figure + KPI rows (not a chart — it is a handful of headline numbers for one pick), states the timeframe, mutes any stat from a sub-30-trade window with a `*`, and must keep its two caveats: the windows **overlap** (recent sits inside the reference, so it is not two independent tests) and everything is a backtest. When nothing qualifies it says so and names the closest miss — never invent a pick.
Columns (Oct 2026, rebuilt for investment comparison — CAGR/6M/1Y/Sharpe removed): Vol · Trades · **Net P/L** · **vs B&H** · PF · Max DD · Win rate · **In mkt** · Stable · Yrs · ✓. `vs B&H` = `(1+net)/(1+bh)−1`, how much richer you ended than holding the same coin over the same window. ✓ requires `net>0 AND edge>0 AND PF≥1.3 AND WR≥30% AND DD≤60% AND ≥30 closed trades AND ≥70% of windows profitable`. On 1h only `liqbrk` produces a real sample (Cycle needs a 200-week MA; Trend/Turtle need months per trade), which is why those rows show 0–2 trades.
- Universe: **BTC ZEC SOL XRP XMR SUI LINK** only (XMR delisted Feb 2024, historical). Any Binance pair still works via free-text search.
- Lookbacks are **day-denominated** and scaled to bars per TF in `runQuant` (stop mults × √(bars/day), floor 0.8) — that's what makes strategies consistent across 4h/1d/1w. Don't add bar-count params (the sole exception is `liqbrk`'s `lbMaBars`, which is bar-native on purpose and documented as such in ALGORITHM.md).
- `detector.js` — the engine (`window.SMC` / Node module). Quant strategies live in `runQuant`; legacy SMC structure code (pivots/FVG/liquidity/walkStructure) remains for chart context and hidden params.
- `index.html` also carries the **session overlay** (`SESSIONS`/`sessionBlocks()`/`drawSessions()`, toggle `#showSessions`) drawn first in `drawOverlay` so it sits under every other layer; auto-hidden on ≥1d. Intraday trade markers read `buy US 18:30` (session + IST).
- `pytester/session_bt.py`, `pytester/liqbrk_v2_test.py` — standalone research runners. They use `data.load()` but do NOT touch `strategies.py`, so `verify.py` still passes.
- `ALGORITHM.md` — **single source of truth** for strategy rules, tuned defaults, and benchmark results (including rejected ideas — read before re-testing anything).

## Strategies (dropdown → `strategy` param)
- `cycle` (default) — BTC halving playbook: two-tranche accumulation at the 200-week MA (zone A + deep zone B, harmonic avg entry, stop 0.65×200w), Pi-Cycle / 40-week exits. See ALGORITHM.md for the validated cycle signals.
- `tsmom`, `donch` — pure CTA trend / turtle breakout.
- `liqbrk` — **buy-side liquidity continuation**. Runs on 15m but is a **SWING system** (holds ~30h, ~6 trades/mo) — do not call it intraday. First close above the 2-day high + above the 5-day SMA + above the **149-bar MA of the selected chart TF** (`lbMaBars`, bar-native by design — the one documented exception to day-denomination; 0 = off) + volume ≥1.3× its daily average → long; stop 3×ATR; trail out below the 1-day low. The 149 MA gates entries only, and every benchmark below predates it. Edge is the MECHANISM (plateau across every param), not a threshold. **`lbBrkExt` (Sep 2026, DEFAULT 1.0 — ON; `lbStop` also 3→4)** additionally requires the close to clear the 2-day high by ≥n×ATR; at 1.0 it lifts WR 30.2→35.6% and PF 1.10→1.33 on a 10-symbol 1h study, but is **not ZEC-validated** — run `pytester/liqbrk_v2_test.py` first. Two further wins measured but NOT shipped (no book-level state in the app): a BTC-momentum veto that turns 2022 positive, and a max-5-concurrent cap that halves drawdown. See ALGORITHM.md. ZEC 15m **full history** (258k bars, 2019-2026): WR 24%, PF 1.39, +199%, maxDD **61%**, 15/31 losing quarters, and it loses for ~2.5 years through the 2022-24 bear. The often-quoted WR 34% / maxDD 13.5% came from a 2-year bull window only — see the CORRECTION in ALGORITHM.md. Treat it as a bull-regime system.
- Removed July 2026 (user decision): `composite`, `meanrev`, `zecdiv` (git history has them). Hidden legacy params: `fvg`, `scalp`, `momo`, `regime`.

## Conventions
- Run locally: `python -m http.server 8910` (or preview config `bos-backtester` in `.claude/launch.json`).
- Benchmarks: Node scripts that `require('./detector.js')`, fetch Binance daily klines, compute all-in equity with 0.1%/side fees, marked-to-market daily drawdown. Always compare vs buy & hold and report WR/DD/CAGR per symbol.
- The user judges strategies by: win rate ≥30%, drawdown, consistency across ≥5 symbols. Don't overfit weak assets (XRP/LINK fail deliberately).
- Equity panel is exposure-based (`Invest %` of equity per hold, 100% = all-in), NOT risk-per-trade sizing.
- If a rule changes, change `ALGORITHM.md` first.
- **Validate on ALL available history, not the cached window.** ZEC 15m reaches back to 2019-03-21 (~258k bars). A 2-year bull slice made `liqbrk` look like a 13.5%-drawdown system when it is really a 61%-drawdown one.
- **There is NO Binance bar-count ceiling.** `fetchKlines` pages backwards via `endTime`, so depth is limited only by the pair's listing date — BTCUSDT 4h reaches 2017-08-17 (19,959 bars, **9.1 years, two halving cycles**). The old `10000` was a self-imposed `max=` on the Bars inputs; a code comment mistook it for an API limit and that error propagated into ALGORITHM.md. Both inputs now allow 60,000. **This mistake cost real accuracy:** the 4.6-year 4h window reported BTC's `liqbrk` drawdown as −14% when over two cycles it is **−39%** (BNB −19%→−38%, DOGE −39%→−74%). Always quote the deep-window drawdown. Encouragingly, window *stability* held or improved on 7 of 10 symbols over two cycles — the short window flattered risk, not the edge.
- **A robust edge is not the same as a worthwhile one — always check `vs B&H`.** Over 9.1 years on 4h, `liqbrk` on BTC returned +837% while holding BTC returned ~+1,800%: trading halved the outcome. Same on LINK/BNB/SOL. The Sep 2026 "BTC is the best symbol" conclusion tested robustness of the edge and never asked whether it beat the asset. It wins outright on assets that chopped or round-tripped (XRP +1,323% vs B&H, AVAX +595%, DOT +491%). Counterweight: it is only in the market **7–13% of bars** at −25% to −44% drawdown vs buy & hold's ~−77%, so BTC is "half the money for an eighth of the exposure" — judge by whether the idle capital has somewhere else to be.
- **Never pick a symbol, or judge a strategy, from one Bars setting.** Measured Sep 2026 (ALGORITHM.md): at 650 bars on 1h `liqbrk` averages ~1 trade per window (DOGE: zero) and its win rate ranges 0–100% purely on where the window ends; even at 4350 bars about half of all window placements disagree on whether a symbol is profitable. What actually separates winners from losers is **regime** (BTC above/below its own 200-day MA: pooled PF 1.71 vs 1.00 on 1h), validated out of sample 4/4. BTC is the only symbol whose edge survives dropping its three best trades on both 1h and 2h.
- `pytester/` — Python desktop tester (Tkinter, no extra deps, `python -m pytester.app`). No bar cap, parquet cache, sweeps, folds, equity curves. **`detector.js` stays the source of truth**; `python pytester/verify.py` must print `ALL STRATEGIES MATCH detector.js` before trusting a number from it.
- **Day trading is dead on this pair (tested July 2026).** Three day-trade variants (intraday breakout, momentum pullback, squeeze expansion) all lost to the swing system (best PF 1.28 vs 2.66). At a ~0.6% average move the 0.2% round-trip fee eats 34% of it, and a 12h hold cap destroys the fat tail that carries the edge (top-5 trades = 44% of gross profit). Don't retry without maker rebates or a proven higher-frequency edge.
- **ZEC 15m is a momentum market, not a mean-reversion one.** A forward-return scan (ALGORITHM.md `liqbrk`) shows top-of-range / above-VWAP / high-RSI states return 2–3× baseline monotonically, while buying "discount" returns *less than random*. Don't build dip-buying or sweep-fade intraday strategies here — three were built and all lost in every fold.
- Warm-up in `runQuant` is **per strategy** (`warm`). Don't reintroduce a global `maLen` guard: on 15m the 200-day MA is 19,200 bars, which silently zeroes out any intraday strategy.
- Advisor panel leads with plain language (% of capital deployed, entry price/date, live P/L); technical readouts live in the collapsed "Technical detail" section below.
